# 星图使用说明

面向使用者，不涉及代码结构。安装包装好后从开始菜单/应用目录启动即可。

## 一、总览

打开就是总览：

- 顶部四个数字：未完成待办、项目、仓库、需要处理（待提交 + 需要更新 + 待推送）；
- 左边「要做的」：未完成待办，按截止日与优先级排序，勾选即完成；
- 右边「仓库」：状态不正常的仓库，落后远端的可以直接点「拉取」；
- 下方「四象限」：按「重要 × 紧急」分成四格，每格列出至多四条待办，可直接勾完成；
  按住任一待办拖到另一格，会跟着改它的「重要 / 紧急」。

四象限的读法：**先做左上（重要且紧急）**；右上（重要不紧急）是长期价值，
别让它一直拖成左上；左下（紧急不重要）尽量快速清掉或推给别人；右下有空再说。

第一次打开（没有任何数据）会显示三步引导：建项目 → 导仓库 → 记待办。

## 二、待办

顶部输入框写一句话，**回车即存**。下面一行是这次添加的属性：

- 归属：挂到哪个项目（默认「未归属」）；
- 优先级：低 / 中 / 高；
- 四象限：**重要 / 紧急** 两个开关。

需要备注、截止时间、关联仓库时点「详细填写…」，或之后在列表里点「编辑」。
有备注时，鼠标停在待办标题上会直接显示备注内容。

**截止时间**：勾选「设置截止时间」后，用日历选日期、用时间控件选时分（可键盘输入），
不再手填字符串；不勾选就是无期限。
列表里显示「剩 3天4h」或「逾期 2小时」，逾期标红。

**到期提醒**：待办到点会弹一条系统通知（窗口在托盘里也会弹）；多条同时到期会合并成
一条汇总。点击通知会回到待办页。同一个截止时间只提醒一次，改了截止时间会重新计时。

筛选条可以按「全部 / 待办 / 进行中 / 已完成」、按项目、按关键字过滤。
勾选框把待办标记为已完成；已完成会加删除线并沉到列表后面。

## 三、项目

「新建项目」填名称、描述、状态（进行中 / 暂停 / 归档）。

每张项目卡显示：仓库数、未完成待办数、前三个仓库名。
右上角的状态药丸点一下可以直接切换「进行中 / 暂停 / 归档」，不用打开编辑弹窗。

卡片上的按钮：

- **编辑**：改名称/描述/状态，或删除项目（删除不会删仓库登记，仓库会变成「未归属」）；
- **加仓库**：打开导入弹窗并预选这个项目；
- **看待办**：跳到待办页并筛到这个项目。

页面底部的「未归属」卡片按实际内容给入口：有未归属仓库显示「去仓库页」，
有未归属待办显示「去待办页」，两者都有就两个按钮都给。

## 四、仓库

### 4.1 导入

点「导入仓库」，三种方式可以混用：

1. **从本地文件夹**：点「选择文件夹…」，可多选。星图会读每个目录的 `.git`：
   - 有 origin → 用 `owner/repo` 作名字，并按域名识别平台；
   - 没有远端 → 用文件夹名（平台留空，只做本地 git 操作）；
   - 同时读出当前分支、ahead/behind、最近提交，并算出状态。
2. **从远程地址**：先选平台（GitHub / Gitee / Gitea / AtomGit），再粘贴多行 `owner/repo`；
   直接贴完整地址也行——**域名决定平台**（`https://gitee.com/o/r.git`、`git@atomgit.com:o/r.git` 都认）。
3. **读我的仓库**：选好平台、令牌填在「设置 → 工作区」，点「从 <平台> 读取我的仓库」，
   列表会追加进输入框，删掉不想导的即可。

**导入后克隆**：勾上「导入后克隆」，远程仓库会被 `git clone` 到「本地根目录/owner-repo」，
进度显示在页头，已有内容的目录不会被覆盖。不勾就只登记元数据，状态显示「未克隆」。

**进度表现**：
- **本地导入**是重量级任务——原生选择框关闭后，导入弹窗立即关闭，整个窗口变暗并显示进度条，
  逐个目录解析（期间不可操作），完成后记进「工具 → 异步任务」；
- **远程导入**先把仓库写进列表（立刻能看到行），随后的「克隆 / 刷新状态」是轻量任务——
  进度条在页头浅线处，界面照常可以用。

### 4.2 表格

每行一个仓库，列固定：

| 列 | 含义 |
|---|---|
| 仓库 | `owner/repo`，下面一行是本地目录或地址；有评价时悬停仓库名可看评价 |
| 平台 | GitHub / Gitee / Gitea / AtomGit（悬停看主机） |
| 项目 | 归属项目，没归属显示「未归属」；点一下直接弹出项目菜单选择 |
| 分支 | 本地当前分支 |
| 状态 | 待提交 / 需要更新 / 待推送 / 正常 / 未克隆 / 错误（鼠标悬停看原因） |
| 评分 | 重要程度的星数（悬停看「重要 / 可学习 / 难度」三维） |
| 差异 | 改动文件数、领先/落后提交数（`3 改 · ↑2 ↓1`） |
| 最近提交 | 短 hash + 标题，下一行是提交时间 |
| 操作 | 详情 / 拉取 / 提交 / 删除 |

顶部四个数字是全局统计；下面一行可以搜索（仓库名/路径/备注）、按状态筛、按项目筛。

**自动刷新**：表格上方的「自动刷新」开关打开后，可选 10 分钟 / 30 分钟 / 1 小时 /
3 小时。到点自动刷新所有仓库的本地状态和远端信息，异步执行、同时最多跑
「设置 → 常规 → 异步任务 → 最大并发」个；某个仓库失败会跳过并继续，完成后弹
汇总并记进「工具 → 异步任务」。开关和频率会记住，重启后继续生效。

### 4.3 单个操作

- **详情**：打开仓库详情页（见 4.5）；
- **拉取**：`git fetch` + `git pull --ff-only`；
- **提交**：把这一个仓库的改动全部提交并推送（先弹确认框，提交说明可改）；
- **删除**：删掉本机登记（弹确认框）。**磁盘上的代码目录与远端仓库都不会动**，
  之后可以重新导入；改名称/目录走「详情 → 编辑登记」，项目也可直接在表格里点选。

### 4.4 批量操作

勾选任意几行（筛选条右侧的「全选」可一次选当前筛选结果），底部滑出批量条：

| 动作 | 作用 |
|---|---|
| 批量拉取 | 逐个 fetch + pull（快进），适合「早上先同步一遍」 |
| 批量提交并推送 | 逐个 add + commit + push，适合「收工前把改动都推上去」 |
| 刷新状态 | 只读本地 git，不算网络，适合确认「现在到底哪些脏」 |
| 刷新远端信息 | 调平台 API 读默认分支/最近推送/star/issues，适合看未克隆的仓库 |
| 批量删除 | 删除选中仓库的登记（确认一次，全删；不影响磁盘代码） |

批量操作用有限并发执行（「设置 → 常规 → 异步任务 → 最大并发」，默认 4、可调 1–8），
一个完成再补一个；页头浅线处显示进度，结束后弹一条汇总，并记进「工具 → 异步任务」。
**批量提交会把选中仓库里所有未提交改动一并提交并推到当前分支**，确认框里有红字提醒。

### 4.5 仓库详情

从表格的「详情」进入（侧栏不出现这一页）。**返回键在页头标题左侧**（`‹` 图标），
和标题一起固定、不随内容滚动；详情页内不再重复放返回按钮。

页面分三块：

- **README（只读）**：优先读本地仓库根目录里的 README（`.md/.markdown/.txt`/无扩展名，大小写不敏感，
  超过 512 KB 会截断）。本地没有时，点「从远程读取」用令牌拉一次。Markdown 渲染，不提供编辑。
- **我的评价**：三个维度五颗星——**重要程度 / 可学习 / 难度**，外加一段自由评价。
  评的是「这个仓库对我有什么用」，所以它存在本机、跟着仓库走，不会推到代码仓库里。
- **仓库信息**：平台、远端地址、本地目录、分支、最近提交、检查时间、差异；可「编辑登记」或「删除登记」。

## 五、设置

- **工作区（独立分页）**：仓库根目录、各平台令牌（GitHub / Gitee / AtomGit / Gitea），
  Gitea 还要填实例地址；每行都有「测试」按钮，会拉一次该平台的仓库列表验证连通性。
- **Gitea 实例地址支持 http 与 https**：写 `http://gitea.example.com:3000` 就全程走 http
  （网页、克隆、API），写 `https://…` 就走 https——**以你填的为准**，适合内网自建实例。
- **令牌权限**：Gitea 想列「我的仓库」需要 `read:user`（Gitea 的 `/user/repos` 强制要求），
  读仓库信息/README 需要 `read:repository`。如果你只给了 `write:repository`，
  「读取我的仓库」会提示权限不足——两种解法：给令牌补 `read:user`，或在导入弹窗里填「用户名」
  （改走 `/users/<用户名>/repos` 公开列表，不需要 `read:user`）。
- **默认用户名**（设置页最后一行）会带进导入弹窗，作为上面那个「用户名」的默认值。
- 工作区的 GitHub 令牌只给星图仓库页（读列表 / 远端信息 / README）用；
  「关于与诊断 → 仓库同步」里的「同步令牌」只给配置包上传/下载用。两枚独立保存，互不覆盖。
- 令牌只用于「读列表 / 读元信息 / 读 README」；**克隆与推送不用令牌**，走你本机已配置的 git 凭据。
- 令牌只存本机 `settings.json`，不随配置包导出，也不写进日志。

## 六、数据在哪里

`设置 → 查看（关于）→ 基本信息` 里能看到实际路径（Windows 一般是 `%APPDATA%\bestuav-atlas\`），
并提供「打开配置目录」。数据库、日志、配置文件都在那里；「数据与诊断」还能导出一份诊断包。

## 七、常见问题

**Q：状态一直不动？**
A：`需要更新/待推送` 基于上次 fetch 的远端引用。点「批量拉取」或「刷新状态」刷新一次；
如果网络不通，状态不会变，但不会卡住界面。

**Q：拉取报「分叉」怎么办？**
A：`--ff-only` 不允许自动合并。到本地仓库手动 `git pull --rebase` 或处理冲突后再点刷新。

**Q：点了「从列表移除」，代码会删吗？**
A：不会。只删数据库里的登记，本地目录原样保留。

**Q：能同时开多个窗口吗？**
A：默认单实例（再启动会激活已有窗口）。需要多开时在设置里打开「允许多实例」并重启。
