# 定时刷新与页头按钮

> 对应版本：`0.4.5`。本文讲两件事：仓库页的自动刷新是怎么跑起来的，以及新页面怎样在页头标题栏加按钮（包括设置页那种随状态变化的按钮）。

---

## 一、仓库页定时刷新

### 1.1 状态放在哪里

自动刷新**不是页面私有状态**，全部放在 App / settings 上：

| 位置 | 字段 | 作用 |
|---|---|---|
| `settings` | `RepoAutoRefresh` | 开关，持久化 |
| `settings` | `RepoAutoRefreshMinutes` | 间隔，持久化；只接受 10 / 30 / 60 / 180 |
| `App` | `repoRefreshIdx` | 频率分段控件的索引 |
| `App` | `repoAutoOn` / `repoAutoMinutes` | 已应用快照，用来判断「刚开启 / 刚改频率」 |
| `App` | `repoAutoAt` | 下一次触发的时刻（内存中） |

选项列表在 `internal/settings/settings.go` 的 `RepoRefreshMinutes`。设置页没有这组字段；开关和频率只出现在仓库页。

### 1.2 触发链

自动刷新的入口在 `App.View`，每帧顺序是：

```text
App.View
 ├─ syncPages()                  // 页面生命周期 + 闲置销毁
 ├─ checkTodoDue(c)              // 待办到期提醒
 ├─ checkRepoAutoRefresh(c)      // 仓库自动刷新
 └─ 构建 shell / 当前页面
```

`checkRepoAutoRefresh` 的逻辑：

1. 开关关闭 → 清空 `repoAutoOn` / `repoAutoAt`，return；
2. 第一次运行、刚开启或刚改频率 → 下一次 = 现在 + 间隔，return（不会开启就立刻联网）；
3. 还没到点 → `c.After(time.Until(repoAutoAt))`，return；
4. 到点 → 先把下一轮排到「现在 + 间隔」，再判断能不能跑：
   - `taskRunning` / `heavyRunning` / `atlasUI.busy` 有任意一个 → 跳过这一轮；
   - 没有仓库 → 跳过；
   - 否则 `runRepoBatch(batchAuto, allRepoIDs(), "")`。

`c.After` 是 mygo 的定时唤醒：引擎会把它落到主窗口的 `time.AfterFunc` 上。不是每 10 分钟起一个 goroutine，而是**空闲时由定时器唤醒一帧，有动画/悬停帧时每帧顺手检查**。

### 1.3 到点后实际做什么

`runRepoBatch` 启动一个 worker pool，并发上限来自「设置 → 常规 → 异步任务 → 最大并发」（`asyncLimit()`）。每个 worker 处理一个仓库：

```text
batchAuto
 ├─ refreshRepoStatus(r)          // 本地 git：dirty / ahead / behind / 最近提交
 └─ 如果该平台有令牌
      └─ refreshRemoteOne(...)    // 远端：默认分支 / 最近推送 / star / issues
```

约定：

- 没有令牌不算失败，只刷本地状态，远端部分静默跳过；
- 某个仓库远端报错只记一条失败，worker 继续取下一个；
- `refreshRemoteOne` 会把本地状态原因拼在远端文案后面，不会把「3 个文件改动」冲掉；
- 完成后 `reloadAtlas()`、弹 toast、写一条「轻量级」任务记录；
- 自动刷新成功**不撒彩带**，避免后台节奏干扰；
- 窗口在托盘里时 `notifyTaskDone` 补一条系统通知；窗口可见时不发。

失败仓库不会停下来等修复，下一轮会再次尝试。

### 1.4 和页面缓存清理的关系

**不冲突，页面清理后仍然会跑。**

页面缓存（`internal/view/pagelife.go`）销毁的是：

- `pageState` 里的滚动位置、页面私有 `data`；
- 页面自己登记的 `pageAsync` 加载任务（`destroyPage` 会调用 `cancelLoad`）。

自动刷新用的是 App 级字段和 App 级的 `runRepoBatch`，不在 `pageState` 里，所以：

- 仓库页闲置超时被销毁，`checkRepoAutoRefresh` 照常执行；
- 切到别的页面、仓库页不再构建，定时器仍然有效；
- 刷新完成时 toast、任务记录、数据刷新都是全局的；
- 回到仓库页时页面重建，但开关、频率、下一次刷新时间都还在；
- 页面被清理不会中止**已经启动**的那一批刷新；关掉开关也只停后续轮次，不会取消正在跑的批次。

如果以后想改成「只在仓库页可见时刷新」，应该在 `navItem.policy.onEnter/onLeave` 里做门控，而不是依赖页面缓存。

### 1.5 会跳过 / 会停的情况

| 情况 | 行为 |
|---|---|
| 关掉自动刷新 | 清空定时器，后续不再触发 |
| 应用退出 / 主窗口销毁 | 定时器随窗口结束 |
| 已有批量任务或重量级任务 | 跳过这一轮，按完整间隔排下一轮，不排队堆积 |
| 正在读取仓库列表 / `busy` | 同上 |
| 没有仓库 / 安全模式无数据库 | 空跑，不报错 |
| 系统休眠 / 挂起 | 定时器延后；恢复后补一轮，下一轮从恢复时的「现在 + 间隔」算，不补跑多轮 |
| 当前批次仍在跑时关开关 | 当前批次跑完；不再安排下一轮 |

### 1.6 测试与手工验证

自动化：

- `TestRepoAutoRefreshControls`：开关、四档频率写回 settings；
- `TestBatchAutoRefreshesLocal`：无令牌时 `batchAuto` 仍写本地状态，不报错；
- settings 的 round-trip / 脏值归一测试。

手工：

1. 仓库页打开「自动刷新」，选 10 分钟；
2. 观察页头浅线进度、任务记录里的「自动刷新」条目；
3. 切到别的页面或让仓库页闲置超过页面缓存 TTL，等下一轮——仍然会刷新；
4. 托盘/隐藏窗口时完成，应收到系统通知。

## 二、页头标题栏按钮

### 2.1 静态图标按钮：优先走注册表

页头按钮的真源是 `internal/view/registry.go` 的 `navItem.tools`：

```go
{
    id: "orders", label: "订单", icon: icons.Table, build: (*App).orderPage,
    tools: []toolAction{
        {
            icon: icons.Plus,
            label: "新建订单",
            tip: "打开新建订单弹窗",
            run: func(a *App) { a.openOrderDialog() },
        },
    },
}
```

`toolAction` 定义在 `internal/view/header.go`：

```go
type toolAction struct {
    icon  *ui.SVG
    label string        // 无 run 时作为轻量任务名
    tip   string        // 悬浮提示
    run   func(a *App)  // 实际动作；nil = 演示一条轻量任务
}
```

渲染链：

```text
shell.Content.Tools
 └─ App.headerTools
     ├─ pageToolsFor(a.page)   // 从 navItem.tools 取
     └─ toolButton             // 28×28 图标按钮 + Tooltip
```

注意：

- **真实动作一定要写 `run`**；不写会走默认的「演示一条轻量任务」，看起来像按钮没接上；
- 图标统一用 `internal/ui/icons` 里的线性 SVG；
- 页头工具区是横向滚动容器：按钮多/窗口窄时横向滚动，不会把标题挤爆；滚动条被 `ScrollbarInsets` 推到可视区外，视觉上保持一条干净的页头；
- 静态按钮适合「任何时候都能做」的动作，例如待办页的「新建待办」、项目页的「新建项目」、任务页的「轻量任务 / 彩带」。

### 2.2 设置页那种动态按钮：在 `headerTools` 里做特例

设置页的更新按钮**不在注册表 tools 里**，因为它要随检查状态变：

- 没有更新 → 28×28 下载图标；
- 正在检查 → 呼吸点 + 图标；
- 有更新且未忽略 → 高亮「更新」胶囊；
- 安装中 → 「更新中」胶囊，禁用。

`headerTools` 对设置页单独放行并追加：

```go
if len(tools) == 0 && a.page != "settings" {
    return
}
// ... 画注册表里的 tools ...
if a.page == "settings" && !a.safeMode {
    a.updateHeaderButton(c, t)
}
```

`updateHeaderButton` / `updatePill` 是模板：

```go
func (a *App) updateHeaderButton(c *ui.Context, t *ui.Theme) {
    switch {
    case a.updateInstalling:
        a.updatePill(c, t, "更新中", false, "")
    case a.availableUpdate != nil && !a.updateDismissed:
        a.updatePill(c, t, "更新", true, "发现新版本…")
    default:
        btn := ui.Row(c).Shrink(0).AlignItems(ui.Center).Justify(ui.Center).
            Width(28).Height(28).Radius(t.Radius)
        if btn.Hovered() {
            btn.Background(t.SurfaceHover)
        }
        btn.Tooltip(a.updateTip())
        btn.Children(func() {
            ui.Icon(c, icons.Download).FontSize(16).TextColor(t.TextMuted)
        })
        if btn.Clicked() {
            a.checkForUpdates(true)
        }
    }
}
```

给别的页面加同类按钮的步骤：

1. 在 `headerTools` 的早退条件里放行该页（像 `a.page != "settings"` 一样）；
2. 在工具行末尾加一个分支：
   ```go
   if a.page == "orders" {
       a.ordersHeaderButton(c, t)
   }
   ```
3. 写一个绘制函数，按状态画 28×28 图标或高 28 的胶囊；点击调 App 方法；
4. 必须带 `Tooltip` 和可访问标签，别只画一个裸图标；
5. 用 `renderPageSized` + `tt.Find` / `tt.Click` 补一条 UI 测试。

**选型建议：**

- 固定入口、无状态 → 注册表 `tools`；
- 随 App 状态变化、需要文字胶囊、需要呼吸点/进度 → `headerTools` 特例，参考更新按钮；
- 需要下拉/菜单 → 用 `ui.PopoverMenuButton` 或 `choice.Dropdown` 自己搭，不要硬塞进 `toolAction`。

### 2.3 布局约束

- 页头总高 `shell.HeaderHeight`（52 DIP）；
- 标题和工具都在同一行：标题左侧是可选 `Leading`（返回键），右侧是 `Tools`；
- 标题可被压缩/省略，工具区 `Shrink(1)` + 横向滚动兜底；
- 图标按钮统一 28×28；胶囊高度 28，左右内边距 12；
- 工具区不要放输入框、宽表格、多行控件——那是页面正文的事；
- 工具区滚动条是刻意隐藏的，不要依赖「用户能看到滚动条」来发现更多按钮。

### 2.4 现有例子

| 页面 | 按钮 | 方式 |
|---|---|---|
| 待办 | 新建待办 | 注册表 `tools` |
| 项目 | 新建项目 | 注册表 `tools` |
| 异步任务 | 轻量任务 / 演示彩带 | 注册表 `tools` |
| 仓库 | 刷新状态 / 刷新远端信息 / 导入仓库 | 页面顶部操作行（不进页头工具区，避免和正文入口重复） |
| 设置 | 检查更新 / 更新胶囊 | `headerTools` 特例（动态状态） |
