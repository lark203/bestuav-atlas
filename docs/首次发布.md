# 首次发布手册

这份手册是给「bestuav-atlas」的**第一次发版**用的，按顺序做即可。
目标：让一台装了旧版本的机器，能通过应用内的「设置 → 检查更新」自动升到新版本。

---

## 一、更新签名的密钥（最关键的一步）

自动更新靠 **ed25519 签名**保证安全：

- **公钥**固化在程序里（`mygo.json` 的 `updates.publicKey`），用来验证更新包；
- **私钥**只在发版机器与 CI 上，用来给更新包签名。

生成器已经执行过一次 `go tool mygo keygen`，结果如下：

| 文件 | 位置 | 用途 |
| --- | --- | --- |
| `mygo-update.pub` | `C:\Users\wangss\AppData\Roaming\mygo\update-keys\bestuav-atlas\mygo-update.key` 同目录 | 公钥，**已自动写进 `mygo.json`**，不用手动改 |
| `mygo-update.key` | `C:\Users\wangss\AppData\Roaming\mygo\update-keys\bestuav-atlas\mygo-update.key` | 私钥，**绝不入库**，只在发版机器与 CI 用 |

### 需要你做的两件事

**1）把私钥配成 GitHub Actions 的 Secret**

打开 `https://github.com/lark203/bestuav-atlas/settings/secrets/actions` → **New repository secret**：

| 项 | 值 |
| --- | --- |
| Name | `MYGO_UPDATER_PRIVATE_KEY` |
| Secret | `C:\Users\wangss\AppData\Roaming\mygo\update-keys\bestuav-atlas\mygo-update.key` 文件里的**整行内容**（一段 base64，约 88 个字符） |

填完后 CI 才能给更新包签名。没配这一项时，`.github/workflows/release.yml` 的
`Check update signing key` 步骤会直接失败并给出提示——这是**故意**的，
因为无签名的更新包客户端一律拒绝。

**2）把私钥备份到密码管理器**

私钥丢了，已安装的客户端就再也无法验证新版本，只能让用户重新下载安装。

> 若私钥泄露：重新跑 `go tool mygo keygen -force -o <目录>`，把新公钥写回
> `mygo.json` 并重新发版。**旧版本客户端不认新公钥**，必须让用户手动重装一次。

## 二、把代码推上去

生成时已经 `git init` 并配好 `origin`（指向 `https://github.com/lark203/bestuav-atlas.git`），
只差推送：

```bash
git push -u origin main
```

推送前确认仓库已在 GitHub 上创建好（本地不会替你建仓库）。

## 三、发第一版（v0.1.0）

发布流程由 `.github/workflows/release.yml` 驱动，触发条件是**推送 tag**：

```bash
# 1) 确认版本号（当前是 0.1.0）
grep version mygo.json

# 2) 打 tag：必须是 v + mygo.json 里的 version，CI 会校验
git tag v0.1.0
git push origin v0.1.0
```

CI 会在三个原生 runner 上各打一包，并上传到同一个 **draft release**：

| 产物 | 说明 |
| --- | --- |
| `*-setup-*-amd64.exe` | Windows 安装包（NSIS，装到 `%LOCALAPPDATA%\Programs`） |
| `*-windows-portable.zip` | Windows 免安装版（英文名 zip，解开即用） |
| `*.dmg` | macOS 安装镜像 |
| `*.deb` / `*.tar.gz` | Linux 包 |
| `update-<target>.json` | **签名后的更新清单**，客户端「检查更新」读的就是它 |
| `SHA256SUMS` | 产物校验和 |

draft 对客户端不可见，确认产物没问题后转正式：

```bash
gh release edit v0.1.0 --draft=false --latest
```

## 四、验证自动更新

1. 装上刚才的 `v0.1.0`（或用便携版）；
2. 改 `mygo.json` 的 `version` 为 `0.1.1`，提交；
3. `git tag v0.1.1 && git push origin v0.1.1`，等 CI 跑完并转正式；
4. 打开应用的「设置」——标题栏右侧出现高亮的更新按钮，点它按提示安装；
5. 应用重启后版本变成 0.1.1，说明整条链路通了。

注意：只有**打包后**的应用才支持更新（`go run` 属于开发模式，设置页会提示
「仅发布版支持更新」）。

## 六、常见问题

**为什么 Release 里的免安装版是英文 zip、不是中文 exe？**
GitHub Releases 不接受中文资产名，上传 `星图.exe` 会被静默改成 `default.exe`。
所以 `scripts/make-portable-zip.py` 把它包成英文名 zip，zip 内部仍是中文文件名。

**tag 和 mygo.json 的 version 对不上会怎样？**
CI 的 `prepare` 作业会直接失败并说明期望的 tag 名。版本号错位会让客户端更新到
错误的包，所以这里刻意做成硬失败。

**CI 里没有 Python 吗？**
三个 GitHub 托管 runner 都自带 Python，`make-portable-zip.py` 直接用。

**本地想打 Windows 包？**
```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-windows.ps1
```
该脚本会自动从 `%APPDATA%\mygo\update-keys\bestuav-atlas\mygo-update.key` 读取私钥，
所以本地出包也是签过名的。
